# Topics beyond construction

The format works for any system that exists because something kept failing. A topic qualifies if you can name a crude first version and at least four real failures that forced a fix.

## Check demand first
Do this before writing, and tell the user the result.

1. Search short videos for the plain topic, sorted by views.
2. Record the top view counts. Several results over 10M is strong demand.
3. Search the exact format, "How a X Becomes a Y". Low views mean the format is open. Moderate views mean it has been tested.
4. Note what the top results are. Real-world builds prove the topic, not this animated style, so say so.
5. Score it for this format: can the whole story show in one cross-section, and are there people doing visible work?

No topic is guaranteed to go viral. Report the evidence and never promise views.

Never reuse a topic a channel you are studying has already made, even if it was their best. Find the closest original with the same trigger.

Three films made this way:

| Topic | Demand found | Why it fit |
|---|---|---|
| Snowdrift to igloo | 50M, 32M, 25M, 13M | Survival stakes, open format |
| Dirt pile to castle | 20M, format tested at 401K | Named history, one great story |
| Muddy hole to water well | 57M, 24M, 21M, 9.6M | Vertical cross-section, lots of visible work |

## Good lanes
| Lane | Example title | Crude start |
|---|---|---|
| Software | How a Login Form Becomes a Bank | A text box that checks a password |
| Money | How a Shoebox Becomes a Bank | Cash in a shoebox |
| Internet | How a Long Wire Becomes the Internet | Two computers and a cable |
| Health | How a Bowl of Soap Becomes a Hospital | A bowl by the door |
| Food | How a Bucket of Milk Becomes a Supermarket | A bucket on a porch |
| Everyday objects | How a Stick Becomes a Zipper | A stick through a loop |

These are starting ideas. Check every fact before writing.

## Turning abstract things into objects
The viewer must be able to see the idea with the sound off. Never show a slide, code or a chart. Give every abstract thing a body.

| Idea | Show it as | Engine piece |
|---|---|---|
| Data, messages, requests | Crates on a belt or beads in a pipe | `Crate`, `FlowPipe` |
| Server, database, vault | A cabinet of lit slots | `Rack` |
| Network, wire, API | A pipe between rooms | `FlowPipe` |
| Password, key, identity | A physical key and a lock | Build as a prop |
| Attacker, failure | A red figure or a red crate | `ScaleFigure`, `Crate` |
| Cache, queue | A shelf, a waiting line | `Crate` |
| Encryption | A crate sealed into a locked box | Build as a prop |
| Load, traffic | Many crates arriving at once | Seeded `Crate` list |
| Rule or process | A gate that opens or stays shut | Build as a prop |

## Choosing a setting
- `Backdrop` with `CutGround`: outdoor builds where the ground matters.
- `Studio`: rooms, machines, software and abstract systems.
- A section view still applies. Cut open the wall, cabinet or machine instead of the ground.

Keep one setting for the whole film, so the world still persists.

## Rules that do not change
Keep the same line-one joke, failure chain, camera rules and ending in every lane. "If you put a text box on a page and check it against a list, you have a bank" follows the same logic as "you have a log cabin".
